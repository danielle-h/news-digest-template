# תבנית לתקציר חדשות יומי עם AI

תקציר חדשות יומי בחינם, שמגיע למייל. הוא קורא אתרי חדשות מכל קצוות הקשת הפוליטית, מבקש מ-Gemini
לסכם את היום ולהשוות איך כלי תקשורת עם נטיות שונות מציגים כל סיפור, ושולח לכם את התוצאה. הוא רץ כל
בוקר ב-GitHub Actions, זוכר את הסיפורים מהימים הקודמים כדי לעקוב אחריהם לאורך זמן, ובימי שישי שולח
סיכום שבועי.

המקורות והניסוחים בדוגמה עוקבים אחרי חדשות מישראל בעברית ובאנגלית, לצד כלי תקשורת בינלאומיים. אפשר
להתאים אותם לכל נושא: ראו [התאמה לנושא שלכם](#התאמה-לנושא-שלכם).

הכול רץ על השכבות החינמיות: ה-API החינמי של Gemini, דקות של GitHub Actions ו-Gmail.

## מה יש בכל מייל

- **התקציר היומי:** הסיפורים המרכזיים, עם הערת "איך זה מוצג" כשכלי תקשורת מימין ומשמאל מציגים
  את הסיפור אחרת; עדכונים על סיפורים ישנים שחזרו לכותרות; סיפורים שרק צד אחד מסקר; חדשות מהעולם;
  ו"ולסיום", סיפור אחד טוב, מצחיק או משעשע. כל טענה מקושרת לכתבה המקורית.
- **הסיכום השבועי (בימי שישי):** איך התפתחו הסיפורים שנמשכו כמה ימים, מה נרגע, איך השתנה הסיקור,
  ומה כדאי לעקוב אחריו בשבוע הבא. הוא נכתב מתוך הרשומות היומיות, כך שהוא לא חוזר על התקצירים
  היומיים.

## הקמה

### 1. יוצרים עותק משלכם

לוחצים על **Use this template** בראש העמוד ויוצרים מאגר **פרטי** (private). זה חשוב שהוא יהיה
פרטי: ה-workflow שומר את היסטוריית הסיפורים שלכם במאגר בכל יום.

### 2. משיגים את פרטי הגישה

- **מפתח Gemini API:** יוצרים אחד ב-[Google AI Studio](https://aistudio.google.com/apikey).
- **חשבון Gmail לשליחה בלבד:** עדיף לפתוח חשבון חדש ולא להשתמש בחשבון הראשי. מפעילים אימות
  דו-שלבי, ואז יוצרים סיסמת אפליקציה בכתובת <https://myaccount.google.com/apppasswords>. אם
  הסיסמה תדלוף אי פעם, היא תחשוף רק תיבת דואר ריקה.

### 3. מוסיפים אותם למאגר

במאגר שלכם נכנסים ל-**Settings > Secrets and variables > Actions** ומוסיפים:

| שם | סוג | ערך |
|---|---|---|
| `GEMINI_API_KEY` | Secret | מפתח ה-Gemini שלכם |
| `GMAIL_ADDRESS` | Secret | כתובת ה-Gmail ששולחת |
| `GMAIL_APP_PASSWORD` | Secret | סיסמת האפליקציה |
| `MAIL_TO` | Variable | לאן לשלוח; כמה כתובות מופרדות בפסיקים |

משתנים אופציונליים:

| שם | תפקיד |
|---|---|
| `DIGEST_LANGUAGE` | `English` (ברירת המחדל) או `Hebrew`, שמקבל עימוד מימין לשמאל ושמות כלי תקשורת בעברית. שתי השפות נבדקו בתקציר היומי; הסיכום השבועי נבדק רק באנגלית. שפות אחרות יעבדו, אבל לא נבדקו |
| `ELECTION_SECTION` | `on` מוסיף פרק בחירות (הניסוח כתוב לבחירות בישראל; לבחירות אחרות ערכו את `ELECTION_SECTION` ב-`digest.py`) |
| `GEMINI_MODEL` | המודל הראשי; ברירת המחדל היא `gemini-flash-latest` |
| `GEMINI_FALLBACK_MODEL` | משמש כשהמודל הראשי עמוס; ברירת המחדל היא `gemini-flash-lite-latest`. אפשר לרשום כמה מודלים מופרדים בפסיקים, והם ינוסו לפי הסדר |

אף פעם אל תדביקו מפתחות או סיסמאות בצ'אט עם AI, ואל תשמרו אותם במאגר.

### 4. מריצים

נכנסים ל-**Actions > Daily news digest > Run workflow**:

- `feeds` בודק כל מקור מהשרתים של GitHub ולא שולח מייל. כדאי להתחיל בזה.
- `preview` כותב את התקציר היומי לקובץ שאפשר להוריד מעמוד ההרצה, ולא שולח מייל. טוב לניסוי
  שינויים.
- `test` שולח תקציר יומי במייל בלי לשמור כלום, כך שהתקציר המתוזמן הבא לא מושפע.
- `daily` שולח את התקציר.
- `weekly` שולח את הסיכום השבועי (צריך קודם כמה ימים של היסטוריה).

השדה האופציונלי **language** קובע את השפה להרצה הזאת בלבד, למשל `Hebrew`.

מכאן זה רץ לבד: התקציר היומי ב-03:17 UTC והסיכום השבועי בימי שישי ב-04:23 UTC. את השעות משנים
ב-`.github/workflows/digest.yml`.

## התאמה לנושא שלכם

1. **מקורות:** עורכים את `feeds.json`. לכל רשומה יש:
   - `name`, `url` (פיד ה-RSS), `lang` (`en`, `he`, …).
   - `lean`: הנטייה הפוליטית או הזווית של כלי התקשורת. המודל רואה אותה כדי להשוות בין דרכי
     ההצגה.
   - `region`: לאיזו קבוצת מקורות הוא שייך. בדוגמה יש `israel`, `world` ו-`light` (חדשות קלות,
     רק בשביל "ולסיום").
   - `site` (אופציונלי): הדומיין של האתר. כשהפיד של האתר נכשל, או כשאין לו פיד, הסקריפט קורא
     חיפוש של הדומיין ב-Google News, ואחר כך ב-Bing News.
   - `also_search` (אופציונלי, דורש `site`): `true` לאתרים שהפיד שלהם מחזיק רק את 10-20 הפריטים
     האחרונים. את שאר היום משלימים מהחיפוש ב-Google News.
   - `window_hours` (אופציונלי): לקרוא אחורה יותר מהרגיל, לפידים שמתפרסמים לעיתים רחוקות.
   - `display_names` (אופציונלי): שם כלי התקשורת בשפות אחרות, לקישורים למקורות כשהתקציר בשפה
     הזאת, למשל `{"hebrew": "הארץ"}`.

   כדי למצוא את הפיד של אתר, נסו להוסיף `/feed` או `/rss` לכתובת שלו, או חפשו קישור RSS בעמוד.
2. **ניסוח ופרקים:** עורכים את `DAILY_PROMPT` ואת `WEEKLY_PROMPT` בראש `digest.py`. הדוגמה
   כתובה לקורא שרוצה "בעיקר חדשות מישראל"; שנו את הפסקה הראשונה, את שמות הפרקים ואת שמות
   האזורים כך שיתאימו ל-`feeds.json` שלכם. הכותרות של האזורים שהמודל רואה נקבעות
   ב-`build_daily_prompt`.

אם אתם עובדים עם עוזר קוד מבוסס AI, הוא יכול לעשות את השינויים האלה בשבילכם. תארו לו את הנושא ואת
המקורות, ובקשו ממנו להתאים את `feeds.json` ואת הפרומפטים.

## הרצה מקומית

```
pip install -r requirements.txt
cp .env.example .env            # then fill it in
python digest.py --fetch-only   # check the feeds, no Gemini or email
python digest.py --dry-run      # write out/digest.html, no email, history untouched
python digest.py --no-save      # send the email without updating the history
```

- `--fetch-only` בודק את הפידים, בלי Gemini ובלי מייל.
- `--dry-run` כותב את `out/digest.html`, בלי מייל, וההיסטוריה לא משתנה.
- `--no-save` שולח את המייל בלי לעדכן את ההיסטוריה.

## איך זה עובד

1. קוראים כל פיד, משאירים רק כתבות שפורסמו מאז התקציר הקודם (עד 48 שעות אחורה), וממספרים כל
   כותרת.
2. שולחים את כל הכותרות ל-Gemini בבקשה אחת, עם הנטייה של כל כלי תקשורת ועם רשומות הסיפורים של
   שלושת השבועות האחרונים.
3. Gemini כותב את התקציר ומצטט מספרי פריטים. הקוד הופך את המספרים לקישורים, כך שהמודל אף פעם לא
   כותב כתובות בעצמו ולא יכול להמציא אחת.
4. שולחים את התקציר במייל, ואז שומרים את רשומות הסיפורים של היום ב-`history.json` ואת שעת השליחה
   ב-`state.json`. ה-workflow שומר את שניהם בחזרה במאגר.

זה pipeline פשוט עם קריאה אחת ל-AI, ולא agent: הקוד מחליט על כל שלב, וזה שומר על התהליך צפוי וזול.

## כדאי לדעת

- **חלק מהאתרים חוסמים את השרתים של GitHub.** בגלל זה פידים יכולים לעבור לחיפוש ב-Google News
  וב-Bing News. בתחתית כל מייל מופיעים הפידים שנכשלו.
- **השכבה החינמית של Gemini עמוסה לפעמים.** הסקריפט מנסה שוב כמה פעמים את המודל הראשי, ואז את
  מודלי הגיבוי לפי הסדר. אם כל הניסיונות נכשלים, ההרצה נכשלת ו-GitHub שולח לכם מייל.
- **GitHub מתחיל הרצות מתוזמנות באיחור,** לפעמים של שעות. זה רגיל ב-workflows מתוזמנים בחינם.
  התזמון משתמש בדקות לא עגולות, וזה עוזר; אם צריך שעה מדויקת, הפעילו את ה-workflow מתזמן חיצוני.
- **המיילים הראשונים עלולים להגיע לספאם** עד שתסמנו את השולח כבטוח.
- **היסטוריה:** רשומות בנות יותר מ-45 יום נמחקות אוטומטית.
